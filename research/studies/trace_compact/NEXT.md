# Next steps after the compact-cache comparison

The pass/value/search diagnostic and its fresh 80-game rescaling ablation have now completed. Both external primary gates failed; search defaults remain unchanged. See [endgame_search](../endgame_search/README.md) and its [updated follow-ups](../endgame_search/NEXT.md). The design below records the independent interventions that motivated this follow-up.

Keep the fastest measured complete execution path as the control. Report compact versus dense and full-prefix separately for each mode, as well as compact joint versus compact sequential and full-prefix joint. A faster learned-opponent decoder can still be slower than known-policy joint execution; fewer logical bytes do not establish MFU. Record the repeated primary gate unchanged, including a failure.

The next independent learning task is a bounded pass/value/search diagnostic on retained real-KataGo games. Use all recorded student turns immediately after opponent passes (not selected winning examples), with a prospectively fixed comparison sample of other turns. Pin game files, openings, model elements, exact native replay, rules, inference configuration and source. Reproduce the recorded expert policy/value and 16-simulation Gumbel decision first. Retain every mismatch. Then compare counterfactual searches with value rescaling on/off under identical priors, predictions and budgets, instrumenting root child values/visits and exact terminal-pass backups. The native implementation divides child-value differences by their range, floored at 1e-8; whether this explains the observed refusals remains a hypothesis. Include the teacher where its complete model lineage can be resolved. Do not change caps, infer an Elo gain from recorded positions or substitute this post hoc diagnostic for fresh games.

A resulting search/loss intervention must be a new frozen ablation. Check illegal probability, expert KL, pass behavior, value calibration and real-KataGo completion/score with paired openings and fixed checkpoints. The preceding board-input pilot failed its external gate and does not authorize a second seed under that unchanged protocol. Any new experiment needs its own hypothesis and budget; stronger-play evidence must precede long training.

For systems, move cache receipt ownership into Rust as a separate intervention. The owner should store the selected branch and accepted actions beside each native game and emit compact controls directly. Keep the dense and compact layouts available, validate output controls against the unchanged Python coordinator, and test atomicity, stale tickets, episode/reset/inactive rows, captures, legality-corrected final moves, cancellation and model/context changes. Avoid claiming the speed of a future native implementation by subtracting Python timers. Only then measure the combination with compact KV.

MCTS integration must preserve actual selection and backups. A speculative policy trace is not a completed MCTS decision. A search-node cache can share its evaluated parent history and retain only actual requested child appends, keyed by canonical history, model/context and native generation. Charge cache pool storage, eviction and recovery. Qualify search traces and checkpoint reconstruction before training and fresh KataGo evaluation.

Broader architecture work should distinguish the expert board-state representation from the causal opponent-style representation. Test that as an explicit learning ablation rather than silently removing history from the current model. The separate expert and observed-behavior objectives remain required.

Production still requires durable storage outside this pod, host-loss/partition recovery, separate actor/inference/learner job ownership, promotion of a strong recipe and a bounded sustained training schedule. This execution study does not satisfy those requirements.
