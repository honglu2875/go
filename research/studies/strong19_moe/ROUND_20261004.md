# October 4 MoE research round

The initial all-expert learning screen is complete and reproducible. It gives a modest policy-KL improvement at matched exposure, worse value accuracy, and a large time penalty. The stronger systems result is to keep the encoder dense and add experts only to the temporal transformer. That variant has not yet had a learning run.

## Implementation and controls

Plain JAX, no Flax or new runtime dependency. The importable `gozero.moe` module executes selected FFN assignments with grouped TPU matmuls. Four independent experts, top-two routing, FP32 router logits, BF16 expert products with FP32 accumulation, and no token dropping. Parameters are replicated across the existing data-parallel mesh. Every encoder/router/attention/readout matrix operation is included in the logical cached-move FLOP budget; physical padding, communication and optimizer work are reflected in timings, not hidden by that budget.

The all-expert model has 420,991,764 parameters versus the dense transformer’s 232,011,540, at 1.000637x logical active matrix FLOPs. Both use width 768, a 24-block shared encoder applied twice, an 18-layer causal history transformer, one soft board token and a spatial policy readout. The reference here is the dense transformer, not the historical CNN.

Learning used the identical immutable 19x19 split, complete-game draws and D4 augmentations, 128-game global batches, AdamW and the original 512-update schedule (40-update warmup, peak LR 1e-3). Validation and a fixed training probe ran every 16 updates. The test split remained closed. Both models received 3,596,975 position exposures; these include repeated examples.

At the registered endpoint, policy KL is 4.17% lower, value MSE is 15.16% higher, and top-one accuracy is 40.09% versus 41.95%. The policy benefit shrank from the earlier update-48 result. Recorded learning time is 2.715 hours versus 1.209 hours, a 2.245x penalty. The historical dense update-144 validation fits within that sparse learning-time budget and reached KL 0.813972; this is a historical timing reference, not a concurrent equal-wall-time trial.

The first all-expert model does not meet the efficiency goal. One paired seed and only 24 post-warmup updates cannot establish convergence or playing strength. Early value instability recovered, while the endpoint still has a larger value train/validation gap. All updates were finite and accepted, no tokens were dropped, and complete model/AdamW/RNG checkpoint, rank-consistency, draw-replay and disk-peer audits passed.

## Systems ablations

The 70-case grouped-kernel screen passed every forward/backward numerical check, including concentrated routing, ragged rows, empty experts and the two training buckets. Maximum complete-leaf relative-L2 error against the independent oracle was 0.0036862, under the registered 0.01 gate. Permutation gradients generally gave the best training timings: 1.22–1.27x at temporal shapes and 1.06–1.16x at encoder shapes. Dense-control timing variation makes the smaller differences uncertain. No complete-learner speedup is claimed from these microbenchmarks, and no optimized execution mode was adopted. [All kernel results](../strong19_moe_permute/kernel-review-003/RESULTS.md).

The temporal-only variant keeps every dense encoder parameter and initialization draw unchanged, replacing only the 18 temporal FFNs. It has 317,001,492 parameters (+36.63%) at 1.00000132x logical active matrix FLOPs. Its per-router auxiliary coefficients match the all-expert experiment’s convention. Eleven CPU integration checks and all four full-size TPU systems cases passed.

The larger-chunk BF16 rematerialization proposal failed its predeclared first-moment tolerance and remains unqualified. Unchanged-chunk rematerialization passed CPU checks only. Both the failed result and the unrun proposals are retained.

## Next experiment

Prioritize a 128-update temporal-only learning arm on the same registered draws and full LR schedule, with validation every 16 updates and durable checkpoints at 64 and 128. This gives a longer post-warmup comparison against the existing dense reference. Freeze a separate learning registration after reserving storage for its approximately 3.55 GiB full optimizer checkpoint; the owner needs at least about 9.1 GiB for two payloads plus its reserve, before accounting for other retained files. Current free disk is below that transient requirement, so verified duplicate archival must precede launch.

Compare policy KL, value error, top-one accuracy, train/validation separation and learning time together. Replicate a promising result with a second paired seed before scaling the horizon. Keep router-LR changes and execution changes in separate arms; do not conflate them with expert placement. A complete-learner state/memory/timing gate for permutation gradients is prepared but unrun. There is no newly queued learning job. [Decision details](NEXT_EXPERIMENTS.md).
