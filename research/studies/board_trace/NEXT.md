# Next systems study

The CPU qualification establishes an execution mechanism, not a throughput result. The next implementation should clone this complete recipe into a separate TPU benchmark and freeze a new protocol before running it. The board-conditioned student's failed strength gate remains in its lineage; no additional student training follows from these execution results.

First add a native per-game remaining-work allowance. Each mode must consume exactly the same registered sequential event prefix, across terminal resets, while games that reach the limit remain inactive. Charge padded/inactive network work. Merely running a fixed number of packets compares different numbers of moves and cannot support a throughput claim. Test the allowance on captures, terminal/capped resets, zero remaining work, stale tickets and heterogeneous batch completion.

Use the established multi-host SSH/pdsh executor with frozen source, locked uv environment and attested native builds. Initialize distributed JAX once; use local-device inference so an ordinary move does not introduce cross-host collectives. Keep identical model elements, game/episode/ply keys, board rules and start states in every condition. Qualify TPU sequential-versus-speculative action prefixes before performance screening; do not reuse the CPU result as a TPU numerical guarantee.

The first timing comparison should include one-step execution, learned-behavior k=4 paired decoding, and known-policy k=1 continuation. The known-policy control can additionally remove redundant view computation when both actual self-play policies and draws are available; this changes the execution graph and needs its own numerical qualification. Warm each executable outside measured segments, then use counterbalanced repeated order. Record compile/preparation time separately and retain it in total attempt cost. Set the actual host, batch-size, repetition and time budgets in the new registration after resource preflight.

Primary systems evidence should be equal-prefix wall time and accepted moves/second, with per-host results and a declared repeated-run threshold. Record native start/resolve time, CPU process time across worker threads, device execution/fetch time, logical input/output bytes, active/padded tokens, board encodes, branch predictions, accepted depths, state mismatches and discarded forecasts. Logical tensor bytes are not physical link traffic. Use a JAX/TPU trace to establish whether time is spent in compute, transfers or waits; compiler cost dictionaries alone cannot establish MFU.

The current native trace resolver is serial. After the first comparison isolates the decoding mechanism, adapt the existing persistent Rust worker design to fixed game shards and bounded reusable buffers. Keep each game's mutable board/history on one worker, avoid per-packet thread creation, and isolate frequently written queue metadata. Measure the effect with worker-count sweeps and available CPU cache/cycle counters; do not infer cache benefits from the use of Rust or alignment annotations. Preserve exact event-prefix and ticket checks for each change.

MCTS integration is separate. A future speculative inference cache may provide policy/value outputs only when the search actually requests the same canonical history, exact board input, network version and context. It must preserve the search's own selection and backup logic; a policy trace is not a sequence of completed MCTS decisions. Approximate TPU arithmetic or changed search decisions require another learning/real-KataGo study before promotion.

For model research, the completed external games motivate a separate pass/endgame diagnostic: inspect policy mass and terminal backups after an opponent pass, value calibration on held-out losing positions, and the teacher's corresponding decisions. Freeze any loss, target or search intervention as a new ablation. Do not turn caps into draws/losses, change the existing cap retrospectively, or increase model/training size as a substitute for this diagnosis.
