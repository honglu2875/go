# Follow-ups after the failed rescaling screen

The phase-stratified calibration diagnostic and its subsequent value-loss pilot have now completed. BCE2 failed both the prediction and external criteria after all 144 scheduled KataGo games; retain MSE. See [student_calibration](../student_calibration/README.md), [value_logit_distillation](../value_logit_distillation/README.md) and the [current architecture design](../value_logit_distillation/NEXT.md). The original follow-up rationale below remains recorded.

Keep value rescaling enabled in the existing control. The fresh off arm failed both its positive score-interval and completion requirements. Do not repeat this pilot on more openings until a separate hypothesis and budget have been registered; do not relabel caps or treat extra passes as wins. The completed-root inspection remains useful for future search diagnostics and changes no production default.

The next learning comparison should separate expert representation from opponent-history modeling. The present causal student still has expert KL 1.058 and weak real-KataGo results despite exact board inputs. Train an explicit board-only expert control against the current history-conditioned expert using the same teacher data, split, target losses and training-token budget, with comparable parameter and compute budgets reported separately. Preserve the separate behavior objective and prevent it from updating expert policy/value parameters. A board-only expert is an architectural hypothesis, not an established fix or a replacement for the observed-opponent model.

Before that training comparison, quantify teacher–student errors by game phase and native legality, including pass prior, value calibration and policy divergence, on the existing held-out split. Selection and bins should be fixed prospectively. The 899 late-game positions are largely losses and are not a representative calibration set. Require exact continuation and a preregistered fresh real-KataGo panel for any resulting model. Use training and compute curves to distinguish improved approximation from RL sample efficiency. The current data come from our own teacher mixture; keep external KataGo checkpoints and labels evaluation-only.

The independent systems task remains moving speculative cache receipts into Rust. Own branch selection, accepted actions and generation beside each native game and emit compact controls directly. Compare against the unchanged Python coordinator, including stale/model/context tickets, atomic rejection, inactive games, reset boundaries, captures and legality-corrected final moves. Then measure real complete execution with compact KV on all configured hosts. Subtracting Python timers from current measurements is not a native implementation benchmark.

For MCTS, cache exact evaluated node histories and actual child appends while preserving selection and backups. The policy-only trace speedup is not an MCTS speedup. Shared cache entries need model/context/native-generation identity, bounded storage, eviction and recovery checks before learned self-play experiments.

Production work can proceed independently on actor/inference/learner ownership, bounded scheduling and host/partition recovery. A long training launch still needs a qualified learning recipe and durable replay/checkpoints outside this pod. None of this study establishes stronger 19×19 play, current-KataGo superiority, MFU improvement or production readiness.
