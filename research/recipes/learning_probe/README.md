This is a finite integration qualification that actually trains a small Go model from native self-play. Rust owns rules, MCTS, workers, move selection, finite observation history, and terminal outcome labels. Python dispatches coarse NumPy batches, calls pure-JAX model/update functions, maintains a vectorized replay ring, and writes artifacts.

The recipe owns its complete CNN, group normalization, policy/value heads, masked policy loss, value MSE, explicit L2 regularization, momentum SGD, gradient clipping, D4 augmentation, and training loop. There is no Flax or optimizer-framework dependency. Group normalization is per example, so padded inference slots cannot alter active examples. Policy targets are normalized completed MCTS visits; action temperature is a separate sampling choice. Model weights change only after every root search in a move batch has completed.

The smoke configuration uses 3×3, eight games, two pinned native workers, eight simulations per move, and 96 batches of real moves on CPU. It is not a tuned AlphaZero baseline, a strength claim, a hyperparameter confirmation, or a TPU throughput experiment. Larger studies need separately registered configurations and external matches.

Run the model checks with `JAX_PLATFORMS=cpu python -m unittest discover -s research/recipes/learning_probe -p test_model.py -v`. Then freeze the recipe, build that snapshot's native extension with `ops/build_native.py`, and execute the frozen `train.py` with its resolved configuration, new output directory, and matching native receipt.

Artifacts include metrics, complete/truncated game records and SGFs, a replay export with per-row game/model/action/search metadata, and inference weights with an explicit parameter schema. The trainer verifies that exported weights reproduce inference exactly. These are **not resumable training checkpoints**: unfinished actor games/RNG state and the complete optimizer/replay schedule still need checkpoint/restore support before sustained training. The multi-host TPU learner path, paired KataGo evaluation, replay durability, and recovery remain separate integration work.
