# State-validated paired decoding

This execution recipe reuses the fixed exact-board student from `board_state_distillation`. Its trained `model.py` is copied byte for byte and validated against the checkpoint descriptor. New decoding lives in `decode.py`; no weights are retrained. The student failed its real KataGo strength criterion, so this recipe qualifies execution semantics only.

One JAX scan computes both player views and k sampled continuations over a four-ply horizon. The canonical history KV stays on device within the packet. Each step independently encodes its proposed board, produces expert play logits and a separate observed-behavior forecast, and proposes the next board by placing a stone or preserving it on pass. Captures, suicide and exact superko remain Rust's responsibility.

The packet returns the pre-action board input used for every policy row. Rust compares a candidate own-policy row's action prefix and board input with the actual current game before consuming that row's logits. A move can be legal while its policy input is stale; this must stop before the prediction acts. Exact root states, model/context/episode tickets, tensor shapes, finite logits and sampler consistency are validated for the whole batch before any game advances. Root tensors are copied out and cannot mutate native games.

Only the active player's expert policy and its actual counter-based draw choose moves. Selecting a forecast branch never chooses a different own-policy draw. The behavior head predicts observed moves without becoming an MCTS policy. A known-policy independent control forecasts using the true policy probabilities but fresh draws; a known-policy joint control uses actual self-play draws. The latter information is available in controlled self-play, not against an unknown opponent. A root-state joint control holds the old board constant but undergoes the same Rust input checks.

`cpu_greedy.json` and `cpu_stochastic.json` run four games for 128 packets in each speculative mode. A one-step sequential baseline runs long enough to compare every resulting action, game reset and terminal score. Registered mode thresholds are execution screens only. They cannot establish TPU throughput, CPU scaling, MCTS equivalence, stronger play or MFU. The native batch resolver remains serial, and each new packet prefills the full real history. Input/output bytes, padded tokens, proposed states, discarded continuations and native timing are retained for a later matched-work benchmark.

Model tests independently reconstruct the board input before every action, rebuild each causal prefix and compare all policy rows, check root masking/pass behavior, and verify counter-based noise across packet boundaries. Native tests require a capture to invalidate the following input despite its proposed move being legal, reject stale/malformed roots atomically across games, and preserve terminal/cap semantics.
