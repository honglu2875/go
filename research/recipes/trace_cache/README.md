# Retained device KV for exact-work paired decoding

This complete clone of `trace_precision` keeps its full-prefix model and decoder unchanged and adds cached sequential, learned-behavior k=4 and known-policy joint k=1 modes. Rust still owns all Go transitions and validates each consumed action prefix and board input. The fixed weak student's failed KataGo result and the earlier failed bfloat16 qualification remain in the lineage. Execution uses float32 and highest matmul precision; no model is trained.

Each cached graph gathers the view/sample behind the last validated policy row, erases KV at and beyond the current root input, appends the actual last move, and decodes both views. Hypothetical cache rows beyond a partial acceptance cannot become history. Observed-behavior counts incorporate only Rust's accepted moves. A final move corrected by legality filtering replaces the hypothetical input on the next graph. Retained arrays stay on device, and inactive game arrays remain unchanged.

The host coordinator binds cache reuse to stable batch rows, complete canonical action tapes, episodes, model/context identities and ticket generations. It independently checks the selected branch's prior actions. These are metadata guards, with no Python Go transitions; their cost is measured. Cancellation invalidates the coordinator. A nonempty history with no valid cache fails closed and requires explicit full-prefix reconstruction with current parameters. A fresh-coordinator/process test covers reconstruction of nonempty capture histories, including actual native replay. This is not a complete checkpoint/resume qualification for ongoing distributed cached rollouts.

Six modes consume identical registered per-game work and must match the sequential event stream and final native states before timing and in every repetition. Reusable immutable zero carries are allocated and synchronized during compilation/warmup. Actual retained outputs remain on device and are drained inside each measured interval. Timing includes required history checks, commit validation, scheduling and transfers. Final inspection, event reconstruction and archive writes remain outside segment timing and inside attempt cost.

Counters distinguish native frame bytes from host-to-device input tensors, full-prefix prefill from cached root appends, and returned resolver tensors from logical device-only retained arrays. The cache's logical tensor size and output-volume counters are not measured HBM traffic. Both speculative views still exist; native workers remain serial. Those are separate future changes.

`test_cache.py` exercises repeated real native transitions, heterogeneous accepted depths, inactive rows, captures, terminal/cap resets, corrected final actions, canonical-prefix/ticket tampering, model-version invalidation and explicit reconstruction. Cached policy rows are checked against fresh full-prefix evaluation. CPU and TPU benchmark configurations require separate registrations; exact action/state checks on the actual devices precede any speed criterion. Profiling, when enabled, samples cached behavior on host 0 after timing.
