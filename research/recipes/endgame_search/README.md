# Pass/value/search diagnostic

This clone retains the complete board-state student trainer, model and recovery scripts. `diagnose.py` is a separate CPU research harness; the diagnostic trains no model. It reproduces recorded real-KataGo decisions and compares Gumbel value rescaling on/off for the fixed exact-board student and an explicitly identified CNN teacher component from its training mixture.

The native inspection API exposes completed-root priors, visits, unrounded value sums and terminal child values without finishing or changing search. Binding tests check incomplete/finished rejection, repeated inspection, unchanged finish and terminal-pass backup perspective. The Rust search algorithm and configuration defaults are unchanged.

Preparation verifies all 72 original exact-student game results and candidate/KataGo board transcripts, then replays every position in the new native engine. It retains all 899 candidate turns after opponent passes and a fixed hash-selected sample of 128 other candidate turns. A separate 12-position qualification precedes the full diagnostic. Selection is post hoc with respect to the preceding matches and cannot establish playing strength or justify changing any recorded outcome.

Every case replays its exact full history and compares four 16-simulation searches: student/teacher with rescaling enabled/disabled. Only predictions for an identical full history and feature hash may be memoized between the two settings of one model in one case. Retained leaf logits, values and suffixes allow independent verification. Different search settings may visit different leaves; their evaluator remains fixed. The original student setting must reproduce the recorded action, search value and neural/terminal/simulation counts. Native terminal pass values are checked separately. A pass may correctly concede a loss; increasing pass frequency is not a strength metric.

Run records pin source, corpus, native receipt, model and teacher checkpoint lineage. Four CPU worker groups are bounded and write separate artifacts. `train.py` remains the cloneable parent training implementation; use `diagnose.py` with the frozen diagnostic configuration for this study. Any resulting search/loss intervention requires a new frozen hypothesis and fresh real-KataGo evaluation before larger training.

That fresh evaluation is now complete under `research/studies/endgame_search/katago_spec.json`. `eval/run_endgame_matches.py` executes the registered 80-game on/off panel once. `analyze_matches.py` independently checks the frozen evaluator closure, model/native identities, paired configurations/seeds, transcripts, all native/KataGo boards and completed scores, and the prospectively fixed score/completion criterion. `test_matches.py` covers paired score bounds and rejects assigned caps or duplicated colors. The off arm failed both primary criteria; see the [study](../../studies/endgame_search/README.md).

To re-audit retained matches, run the frozen `analyze_matches.py` with `--workspace-root`, `--protocol`, `--expected-protocol-sha256` and a new `--output` path. Use execution source and protocol hashes from the study; snapshots intentionally exclude `research/studies`, so the protocol comes from the workspace with its pinned hash. Existing raw runs and audit outputs must remain unchanged. The audit loads the explicitly qualified native extension and runs on CPU without new games or training.
