The common evaluation harness must run **real KataGo**, using its official search implementation and a pinned neural checkpoint. Neither generated scores, a random opponent, nor loading KataGo weights into our own MCTS qualifies as a KataGo match.

The benchmark specification pins executable hash/build flags, weight hash/model format, complete engine configuration, rules, board size, komi, search budget or clock, seeds, opening-set hash, color pairs, and adjudication. A match result retains GTP transcripts, SGFs, engine stderr, termination reasons, per-move resource counters, and both identities. Crashes/timeouts are accounted for explicitly. Checkpoint selection and headline testing use separate held-out games.

Start with an official CPU KataGo backend and measure feasible evaluation volume. A TPU inference bridge is a separate implementation effort requiring neural parity and fixed-position search tests while retaining official KataGo search. No GPU is assumed. Report fixed-budget playing strength separately from wall time on different hardware.

The current qualification uses official KataGo 1.18.1 source commit `92ee95c0a4b25fec214da00951ab69e97e207729`, compiled with Eigen 3.4.0 and AVX2. [katago_build.json](katago_build.json) records source, compiler, flags, dependencies, and the executable hash. [katago_9x9.json](katago_9x9.json) pins the official `kata9x9-b18c384nbt-20231025` checkpoint exclusively for 9×9 evaluation. These weights do not enter our training lineage. The downloaded AppImage was incompatible with host libraries and is retained as an unused artifact receipt.

`qualify_katago.py` must execute from an immutable snapshot. It verifies external hashes, builds that snapshot's Rust endpoint, then lets official KataGo search play both colors. Every move is checked by Rust, every resulting board is compared, and a two-pass final score must agree. The successful run completed 73 plies at 16 visits/move and scored W+10.5 in both engines. It retains a real SGF, both GTP transcripts, stderr, binary identities, and termination status. See the [qualification report](../research/studies/rules_qualification/README.md).

```bash
uv run --frozen gozero snapshot research/recipes/harness_probe --config research/recipes/harness_probe/smoke.json
uv run --frozen python -B .gozero/snapshots/<sha256>/eval/qualify_katago.py \
  --snapshot .gozero/snapshots/<sha256> --artifacts-root "$PWD" \
  --output runs/qualification/<new-attempt>
```

The packaging recipe selects a source bundle; this command runs the snapshot's evaluation entrypoint, not the packaging trainer. The original self-play qualification is not a learned-model strength result.

`learned_gtp.py` now loads a pinned recipe/model export and the matching native build, then runs that model's PUCT on CPU. Every leaf in a search uses the root engine's evaluator, including opponent-to-move leaves. It does not select an opponent network based on leaf color. `match.py` runs official KataGo against this endpoint with paired colors, frozen openings/seeds, disjoint explicit CPU sets, per-move search counts and time, transcripts, SGFs, failure/truncation records and conservative pair-level uncertainty. Candidate simulations exclude its separate root evaluation; KataGo's `maxVisits` uses its own convention. These are declared budgets, not equal FLOPs.

The first 9×9 model came from scratch after 418 global updates. Four real games completed on matching boards. The initial harness marked three games failed because it incorrectly demanded identical numeric scores from two different area-scoring conventions. Independent transcript audit verified all four native raw scores; the candidate lost all four games under both conventions. Original failures and the separate audit are retained in the [bootstrap study](../research/studies/learning_bootstrap/README.md). This is a starting measurement, not strong play or an algorithmic improvement.

The default native profile scores the raw final board under strict Tromp–Taylor rules. KataGo 1.18.1 first assigns pass-alive territory in its [area calculation](https://github.com/lightvector/KataGo/blob/v1.18.1/cpp/game/board.cpp); its [history scorer](https://github.com/lightvector/KataGo/blob/v1.18.1/cpp/game/boardhistory.cpp) counts those assigned points. A remaining opposing stone may thus contribute differently. This is deterministic area adjudication in the observed finished games, not a neural score estimate. `friendlyPassOk=false` does not make the two conventions identical. The exact pinned source is available in the external build receipt.

The harness reads the candidate's explicit training profile. For `raw_area`, its score must match the independent grid-flood-fill checker, and a winner disagreement with KataGo fails compatibility. For `pass_alive_area`, its numeric score must match KataGo exactly. Both margins remain recorded, including the independent raw score. [The regression fixture](fixtures/pass_alive_area.json) reproduces an observed W+85.5 raw score versus KataGo W+88.5 on the same board. `audit_scores.py` checks retained transcripts without rewriting original results.

`qualify_scoring.py` checks Rust ownership point by point against a small adapter linked to the pinned, unmodified KataGo C++ scorer (compiled with a 25-point edge capacity). It also replays the four real match regressions through the pinned GTP binary and weights. The qualified run matched 1,351,680 intersections in 8,192 positions across sizes 1–25, and all four GTP boards and scores. The [scoring study](../research/studies/scoring_compatibility/README.md) records exact coverage, inputs and the earlier adapter failure. This establishes the tested adjudication compatibility; larger held-out strength panels, independent learning seeds and 19×19 anchors remain promotion gates.

`panel.py` runs frozen match specifications concurrently, rejecting CPU assignments that overlap physical cores, including hyperthread siblings. Every child preserves the full `match.py` record. Aggregation keeps the declared opponent visit levels separate, preserves color pairs and includes failures; it does not convert small zero-win panels into Elo estimates.

`export_checkpoint.py` exports intermediate committed checkpoints for learning curves without creating a new training run. Schema2 candidate descriptors pin the checkpoint group and rank manifest, model version, source and exact exported parameters. The adapter verifies the full checkpoint file hashes, reads only parameter arrays, and compares every exported array to its checkpoint value. It also requires the training native binary. Schema1 final exports remain supported and are checked against the final record's weight hash. Copy generated descriptors into a study's evaluation directory and freeze the complete match schedule before evaluating a curve.

The export qualification (external or omitted experiment artifact) reproduced the original final-model export byte for byte, then played an identical complete game through both schema versions with identical search counts/values and final score. An earlier checkpoint also ran real Rust/JAX search. This qualifies artifact loading; it is not a learning-curve or strength result.

`selfmatch.py` runs paired matches between two pinned learned checkpoints, with official KataGo acting only as a rules and scoring referee. Both learned engines and the referee must agree after every move and at termination. Each engine has separate physical cores; source/model/native identities, completed simulation counts, transcripts, SGFs and incomplete games are retained. These are relative checkpoint matches, not wins against KataGo. The first FPU smoke had an incomplete game, and its larger panel remains unexecuted. A separately registered Gumbel study subsequently completed64 games under its1,296-ply cap: all10,615 boards and64 scores matched the referee. The harness cancels peers on board/rule/score/budget inconsistencies.

Causal-history models use a distinct checkpoint-verified descriptor (`kind: causal_history_policy`) and `causal_gtp.py`. Their match specs explicitly name `causal_inference`, `inference_native_snapshot` and `inference_native_binary_sha256`; the recursive evaluation-input closure includes the inference contract. Offline model training and native inference have separate source identities. The adapter uses exact root-plus-leaf action histories, full prefill and expert policy/value heads at every leaf. It rejects a game cap plus search-depth allowance that cannot fit its trained context, without silently truncating history. The first four-game qualification is documented in [causal_mcts](../research/studies/causal_mcts/README.md). The existing board-model adapter retained exact actions, boards and search statistics in its nine-move regression.
